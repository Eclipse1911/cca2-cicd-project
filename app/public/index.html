Cloud Computing Service Models

According to NIST SP 800-145, Cloud Computing enables convenient, on-demand network access to a shared pool of configurable computing resources.

IaaS

Infrastructure as a Service

Provides raw compute, networking, and storage. The user manages OS, runtime, middleware, data, and applications.

AWS EC2, Google Compute Engine, Azure VMs
PaaS

Platform as a Service

Provides execution environments, middleware, and database engines. Developer only writes and deploys code.

AWS Elastic Beanstalk, Heroku, Google App Engine
SaaS

Software as a Service

End-user web application fully managed and operated by the cloud vendor over HTTPS.

Google Workspace, Microsoft 365, Slack, Salesforce
🏢

Deployment Models & NIST Characteristics

  • Public Cloud: Multi-tenant infrastructure provisioned for open use by the general public (AWS, GCP, Azure).
  • Private Cloud: Dedicated infrastructure provisioned for exclusive use by a single organization.
  • Hybrid Cloud: Composition of two or more distinct cloud infrastructures bound together by standardized technology.

5 Essential Cloud Characteristics:

1. On-Demand Self-Service 2. Broad Network Access 3. Resource Pooling 4. Rapid Elasticity 5. Measured Service

The DevOps Infinity Loop

DevOps is a set of cultural philosophies, practices, and tools that increases an organization’s ability to deliver applications at high velocity.

1 Plan Agile backlog, sprint planning, Jira/GitHub Issues.
2 Code Git version control, feature branches, pull requests.
3 Build Compiling, artifact generation, Docker packaging.
4 Test Unit tests, integration tests, linting, SAST security.
5 Release Artifact tagging, semantic versioning, container registry.
6 Deploy Kubernetes rollout, canary / blue-green deployment.
7 Operate Infrastructure management, auto-scaling, load balancing.
8 Monitor Log aggregation, metrics (Prometheus/Grafana), alerts.

Jenkins Declarative Pipeline Highlights

Our project implements a declarative Jenkinsfile with robust credential masking and stage execution:

Jenkinsfile snippet Groovy 
pipeline {
    agent any
    environment {
        DOCKER_IMAGE = 'eclipse1911/cca2-app'
    }
    stages {
        stage('Build & Test') {
            steps { sh 'npm test' }
        }
        stage('Docker Build') {
            steps { sh "docker build -t ${DOCKER_IMAGE}:${BUILD_NUMBER} ." }
        }
    }
}

Virtual Machines vs Docker Containers

Unlike Virtual Machines which package an entire Guest Operating System on top of a Hypervisor, Docker containers share the host Linux kernel while isolating processes via namespaces and control groups.

Linux Namespaces: Provide isolation for Process IDs (PID), Network stacks (NET), Mount points (MNT), Inter-process communication (IPC), and Hostnames (UTS).
Control Groups (cgroups): Enforce hard and soft limits on resource usage such as CPU, RAM, and Disk I/O.
Union File System (OverlayFS): Allows layered, read-only base images with a thin copy-on-write (CoW) container layer.
📑

Production Dockerfile Best Practices

  • Minimal Base Image: Using node:20-alpine reduces image size from ~1GB to ~160MB, shrinking attack surface.
  • Layer Caching: Copying package*.json before source files prevents unnecessary npm install on every code edit.
  • Least Privilege: Dropping root privilege by invoking USER node.
  • Built-in HEALTHCHECK: Direct container polling using wget /api/health.

Kubernetes Architecture & Primitives

Kubernetes (K8s) is an open-source container orchestration platform designed to automate deploying, scaling, and operating application containers.

Control Plane: kube-apiserver, etcd (distributed key-value store), kube-scheduler, and kube-controller-manager.
Worker Nodes: kubelet (node agent), kube-proxy (networking rules), and Container Runtime (containerd/Docker).
Deployment (2 Replicas): Maintains desired state, manages ReplicaSets, and executes zero-downtime rolling upgrades.
NodePort Service (30080): Routes external traffic from the EC2 node's port 30080 directly into the active application Pods.
🔄

Rolling Updates & Zero-Downtime

In k8s/deployment.yaml, our rolling update configuration guarantees uninterrupted service availability:

k8s/deployment.yaml YAML 
strategy:
  type: RollingUpdate
  rollingUpdate:
    maxSurge: 1        # Spawns 1 new Pod before killing old
    maxUnavailable: 0  # Guarantees 100% capacity during rollout

When Jenkins issues kubectl set image, K8s launches new Pods, validates Readiness probes, and terminates older Pods cleanly.

🩺

Liveness vs Readiness Probes

Kubernetes uses health probes to monitor and auto-heal containers:

Liveness Probe

Is the container alive?

Checks /api/health. If the application deadlocks or crashes, the kubelet kills the container and initiates an automatic container restart.

Readiness Probe

Is the container ready for traffic?

Determines if a Pod should receive external HTTP traffic from the Service. During rolling updates, traffic only routes after readiness returns 200 OK.

📈

Observability Pillars

  • Metrics: Numeric telemetry over time (CPU utilization, Memory RSS, Request latency).
  • Logs: Discrete event records (stdout/stderr captured by container runtime and indexed via ELK / Fluentd).
  • Traces: End-to-end request lifecycle through distributed microservices (OpenTelemetry, Jaeger).
